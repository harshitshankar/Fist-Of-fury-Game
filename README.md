# 🥊 Fist of Fury — Online Multiplayer Fighting Game

A fast, mobile-first **fighting game** inspired by **Tekken** and **Dragon Ball
FighterZ**, built with **React + Vite + Tailwind** on the front-end and
**Node.js + Express + Socket.IO** on the back-end — packaged as a **single web
service** you can push to GitHub and deploy to **Render** in minutes.

> Create a room, share the **room code**, and your friend joins from anywhere.
> Fight with responsive **touch controls**, taunt over **voice chat**, and end
> every match with a cinematic **"VICTORY MATE!"** slow-motion finish. 🏆

---

## ✨ Features

- **Real online multiplayer** — host creates a room, friend joins with the code.
- **"Room is already full" protection** — every room holds **exactly 2 players**.
  A third player is rejected until someone leaves.
- **24 unique fighters** — each with their own stats, fighting style, signature
  special move and uniquely-colored energy beam (Blaze 🔥, Frost ❄️, Volt ⚡,
  Venom 🐍, Titan 🛡️, Nova 🌟, Ronin ⚔️, Magma 🌋, Tempest 🌪️, Obsidian 🖤,
  Seraph 👼, Reaper 💀, Aqua 🌊, Phantom 👻, Inferna 💃, Goliath 🦏, Spark 🛹,
  Kaiju 🦖, Mystic 🔮, Blade 🗡️, Lumen 🌈, Drakon 🐲, Celesta ✨, Ragnar 🪓).
- **24 detailed arenas** — Ancient Dojo, Neon City, Volcano Crater, Cosmic Void,
  Frozen Peaks, Grand Arena, Enchanted Forest, Desert Ruins, Cyber Grid, Deep
  Abyss, Dark Castle, Cursed Graveyard, Sky Sanctuary, Steel Factory, Jade
  Temple, Thunder Storm, Lost Jungle, Crystal Caverns, Infernal Pit, Celestial
  Gate, Lost Civilization, Frozen Tundra, Neon Carnival and The Void — each with
  animated scenery and its **own unique background music track**.
- **Responsive touch controls** — move, jump, punch, kick, block & special.
  Also playable with keyboard on desktop.
- **Fighting animations & FX** — punches, kicks, screen shake, hit flashes,
  particles, floating damage numbers and meter-based supers.
- **Kamehameha-style energy beams** — each fighter fires a **unique-colored**
  beam (Blaze=fiery orange, Frost=icy blue, Volt=electric yellow, Venom=toxic
  green/purple, Nova=cosmic pink, etc.) with a **blurred outer aura**, white-hot
  core, **spiraling energy helix**, a pulsing charge orb, a bright leading
  sphere and darting sparks. Beams fly at **body/chest height** and **launch the
  opponent flying far across the arena** on hit. Fully synced in online play.
- **Voice chat** — peer-to-peer **WebRTC** voice (no audio touches the server).
- **Text chat** — in-room messaging in the lobby and during the fight.
- **"VICTORY MATE!" slow-motion** — Fortnite-style slow-mo + confetti on a KO.
- **Custom character color** picker + random **room code dice** 🎲 (matches the
  reference UI).
- **Procedural sound effects** — punches, kicks, blocks, special blasts, KO and
  a victory jingle (Web Audio API, no audio files needed). Mute toggle in-match.
- **Background music** — looping chiptune-style soundtracks generated
  procedurally (no audio files): a menu theme in the lobby and a **unique battle
  theme for every one of the 24 arenas** (different scale, tempo & key per map).
  Music on/off toggle in the lobby + the in-match mute covers it too.
- **App-like presentation** — auto-fullscreen + landscape lock and a
  "rotate your device" hint on portrait phones.
- **CPU mode** — practice vs an AI bot offline.
- **Privacy policy page** (`/privacy.html`) ready for app-store submission.

## 🧪 Two Ways to Play — Read This First!

The game has **two parts**:

| Part | What it does | When it runs |
| ---- | ------------ | ------------ |
| **Front-end** (`dist/`) | All the visuals, controls, UI | Anytime the page is open |
| **Server** (`server.js`) | Room codes, matchmaking, "room full", chat & voice relay | **Only when you run `node server.js` OR deploy to Render** |

> ⚠️ **Online play (Create/Join Room) does NOT work unless the server is
> running.** If you only open the built `index.html` file directly, you'll get a
> "Can't reach the game server" message. Use **PLAY vs CPU** for offline play,
> or follow Option A / Option B below to enable online multiplayer.

## ☁️ OPTION A — Deploy to Render Cloud (public URL, friends on any network)

This is the recommended way to play with friends who are on **different devices
and different networks**.

### Step 1 — Put the project on GitHub
1. Create a new empty repository on GitHub (e.g. `fist-of-fury`). Do **not** add
   a README/license (you already have them).
2. In the project folder run:
   ```bash
   git init
   git add .
   git commit -m "Fist of Fury"
   git branch -M main
   git remote add origin https://github.com/<your-username>/fist-of-fury.git
   git push -u origin main
   ```

### Step 2 — Create the Web Service on Render
1. Go to **https://render.com** and sign in (free account works).
2. Click **New +** → **Web Service**.
3. Click **Build and deploy from a Git repository** → **Connect** your GitHub →
   pick the `fist-of-fury` repo.
4. Fill in the settings **exactly**:
   | Field | Value |
   | ----- | ----- |
   | **Name** | `fist-of-fury` (anything) |
   | **Region** | closest to you |
   | **Branch** | `main` |
   | **Runtime / Language** | `Node` |
   | **Build Command** | `npm install && npm run build` |
   | **Start Command** | `node server.js` |
   | **Instance Type** | `Free` |
   | **Health Check Path** | `/health` |
5. Click **Create Web Service**. Render installs, builds, and starts the server.
   First deploy takes ~2–4 minutes — watch the **Logs** until you see
   `🥊 FIST OF FURY server running on port ...`.

> 💡 **Even easier (Blueprint):** This repo includes `render.yaml`. Instead of
> the manual steps, choose **New + → Blueprint**, select the repo, and Render
> fills everything in automatically.

### Step 3 — Play with friends 🎮
1. Render gives you a public URL like **`https://fist-of-fury.onrender.com`**.
2. **You:** open the URL → type a name → **CREATE ROOM** → you get a code
   (e.g. `K7H2P`).
3. **Your friend (any device / any network):** opens the **same URL** → types a
   name → enters the code → **JOIN ROOM**.
4. Both tap **I'M READY** → countdown → **FIGHT!** 🥊
5. If a third person tries the same code they'll see **"ROOM IS ALREADY FULL"**
   until one of the two players leaves.

> ⏰ **Free plan note:** Render's free service "sleeps" after ~15 min of
> inactivity. The first visit after sleeping takes 30–50 seconds to wake — just
> wait on the loading screen, then it connects normally.

> 🔄 **Updating the game:** every time you `git push` to `main`, Render
> auto-rebuilds and redeploys. No extra steps.

## 💻 OPTION B — Run locally (your own computer / same Wi-Fi)

Use this to test before deploying, or to play with someone on the **same Wi-Fi**.

### Quick run (single service — exactly like production)
```bash
npm install
npm run build        # ← REQUIRED: creates the dist/ folder. Do this first!
node server.js
```
Open **http://localhost:3001** in your browser. ✅

> ❗ **Common mistake:** running `node server.js` **without** building first
> shows a blank/placeholder page. Always run `npm run build` first. The server
> now prints a clear warning if `dist/` is missing.

### Test multiplayer on ONE computer
Open **http://localhost:3001** in **two browser tabs/windows**. Create a room in
one tab, copy the code, and join from the other.

### Play across TWO devices on the SAME Wi-Fi
1. Find your computer's local IP address:
   - **Windows:** run `ipconfig` → look for `IPv4 Address` (e.g. `192.168.1.5`).
   - **macOS/Linux:** run `ifconfig` or `ip addr` (e.g. `192.168.1.5`).
2. Keep `node server.js` running on your computer.
3. On the **other device** (phone/laptop on the same Wi-Fi), open
   **`http://192.168.1.5:3001`** (use your actual IP).
4. Create/join rooms as normal.

> If the other device can't connect, allow port **3001** through your computer's
> firewall, and make sure both devices are on the **same** network.

### Live-reload dev mode (for editing the game)
```bash
# Terminal 1 — the multiplayer server
node server.js
# Terminal 2 — Vite dev server with hot reload
npm run dev
```
Open **http://localhost:5173**. In dev the client auto-connects to the server on
`http://localhost:3001`.

## 📱 Build a Downloadable Android App (.apk / .aab)

Both methods below work whether your server is on **Render (Option A)** — best,
gives a public URL — or running **locally (Option B)**. For a real installable
app you should point it at your **Render URL** so it works anywhere.

### 🟢 Method 1 — PWABuilder (fastest, no Android Studio needed)
1. Deploy with **Option A** so you have a public URL.
2. Go to **https://www.pwabuilder.com** and paste your Render URL.
3. Click **Package for stores → Android → Generate Package**.
4. Download the `.apk` (for sideloading/testing) or `.aab` (for Google Play).
5. In Google Play Console, set the **Privacy Policy URL** to
   `https://<your-app>.onrender.com/privacy.html` (this page is already built in).

### 🔵 Method 2 — Capacitor + Android Studio (full native control)

This wraps the game in a native shell and lets you build the APK in Android
Studio.

**1. Install Capacitor in the project**
```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "Fist of Fury" com.fistoffury.app --web-dir=dist
```

**2. Point the app at your deployed game.** Open the generated
`capacitor.config.ts` (or `.json`) and set the server URL:
```ts
import { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.fistoffury.app',
  appName: 'Fist of Fury',
  webDir: 'dist',
  server: {
    // OPTION A (recommended): load the live Render site.
    url: 'https://<your-app>.onrender.com',
    cleartext: false,
    // OPTION B (local testing on same Wi-Fi): use your PC's IP + http.
    // url: 'http://192.168.1.5:3001',
    // cleartext: true,
  },
};
export default config;
```

**3. Add the Android platform**
```bash
npm run build        # make sure dist/ exists
npx cap add android
npx cap sync
```

**4. Add permissions.** Open
`android/app/src/main/AndroidManifest.xml` and add inside `<manifest>` (above
`<application>`):
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.MODIFY_AUDIO_SETTINGS" />
```

**5. Open & build in Android Studio**
```bash
npx cap open android
```
- Android Studio opens the project. Press **▶ Run** to test on an emulator or a
  USB-connected phone.
- To create a shareable file:
  **Build → Build Bundle(s) / APK(s) → Build APK(s)** → find the `.apk` in
  `android/app/build/outputs/apk/`.
- For the Play Store: **Build → Generate Signed Bundle / APK → Android App
  Bundle (.aab)**, create a keystore, and upload the `.aab` to Play Console.

**6. (If using a local Option B URL over http)** add
`android:usesCleartextTraffic="true"` to the `<application>` tag so Android
allows the non-HTTPS connection. Not needed for the Render (https) URL.

> 🎤 **Microphone tip:** Android will prompt for mic permission the first time a
> player enables Voice Chat. Always use **headphones** to avoid echo.

## 💰 Monetize with Google AdMob (Android app) & AdSense (web)

You can earn money two ways: **AdMob** inside the Android app, and **AdSense**
on the web version. They don't conflict.

### 💵 A. Google AdMob (inside the Android app — recommended)

AdMob is built for mobile apps and pays the most for game traffic.

**1. Create an AdMob account & app**
1. Go to **https://admob.google.com** → sign in → **Apps → Add App**.
2. Choose **Android**, give it your app name (it doesn't need to be published
   yet). You'll get an **App ID** like `ca-app-pub-XXXX~YYYY`.
3. Create **Ad Units** (e.g. a **Banner**, an **Interstitial** to show after a
   match, and a **Rewarded** ad for "unlock extra fighter"). Each ad unit has
   its own ID like `ca-app-pub-XXXX/ZZZZ`.

**2. Add the AdMob plugin (Capacitor build)**
```bash
npm install @capacitor-community/admob
npx cap sync
```

**3. Add your AdMob App ID to `AndroidManifest.xml`** inside `<application>`:
```xml
<meta-data
  android:name="com.google.android.gms.ads.APPLICATION_ID"
  android:value="ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY" />
```

**4. Show ads from your app code.** A good pattern for this game:
- **Banner** on the lobby screen.
- **Interstitial** after a match ends (on the "VICTORY MATE!" → back to lobby).
- **Rewarded** to grant a cosmetic or rematch.

Example (call from React, e.g. in `App.tsx` when returning to the lobby):
```ts
import { AdMob, BannerAdSize, BannerAdPosition } from '@capacitor-community/admob';

// once at startup
await AdMob.initialize();

// banner in the lobby
await AdMob.showBanner({
  adId: 'ca-app-pub-XXXX/BANNER_UNIT',
  adSize: BannerAdSize.ADAPTIVE_BANNER,
  position: BannerAdPosition.BOTTOM_CENTER,
});

// interstitial after a match
await AdMob.prepareInterstitial({ adId: 'ca-app-pub-XXXX/INTERSTITIAL_UNIT' });
await AdMob.showInterstitial();
```
> ⚠️ Use **test ad unit IDs** while developing (AdMob provides them). Clicking
> your own real ads will get your account banned. Switch to real IDs only for
> the released build.

**5. Required for AdMob:** in Play Console you must complete the **Data Safety**
form and provide the **Privacy Policy URL**
(`https://<your-app>.onrender.com/privacy.html`). AdMob serves personalized ads,
so you must also show a consent prompt in regions that require it (use Google's
**UMP / User Messaging Platform** SDK — `@capacitor-community/admob` supports it).

### 🌐 B. Google AdSense (web version on Render)

AdSense works on the **website**, not inside the Android app.
1. Go to **https://adsense.google.com**, add your Render URL as a site, and get
   approved (your site must have real content + a privacy policy — you have one).
2. Add the AdSense script to `index.html` `<head>`:
   ```html
   <script async
     src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXX"
     crossorigin="anonymous"></script>
   ```
3. Place an ad slot where you want (e.g. a banner above the lobby):
   ```html
   <ins class="adsbygoogle" style="display:block"
        data-ad-client="ca-pub-XXXX" data-ad-slot="1234567890"
        data-ad-format="auto" data-full-width-responsive="true"></ins>
   <script>(adsbygoogle = window.adsbygoogle || []).push({});</script>
   ```
> Don't put AdSense ad code inside the Android WebView app — that violates
> AdSense policy. Use **AdMob** for the app and **AdSense** for the website only.

## 🏪 Publish to the Google Play Store (step by step)

1. **Pay the one-time $25 fee** and create a **Google Play Console** account at
   **https://play.google.com/console**.
2. Click **Create app** → set name, language, "Game", Free/Paid.
3. **Upload your release `.aab`** (from Android Studio:
   *Build → Generate Signed Bundle/APK → Android App Bundle*). Sign it with a
   keystore and **keep that keystore safe** — you need it for every update.
4. Fill in the **Store listing**: short & full description, app icon (512×512),
   feature graphic (1024×500), and at least **2 screenshots** (take them from
   the game).
5. Complete the required policy forms:
   - **Privacy Policy URL** → `https://<your-app>.onrender.com/privacy.html`
   - **Data Safety** form (declare: mic for voice chat, no data stored).
   - **Content rating** questionnaire.
   - **Target audience** & **Ads** declaration (say *Yes, contains ads* if using
     AdMob).
6. Create a **Production release**, roll out, and submit for review. Review
   usually takes a few hours to a couple of days. 🎉

> 💡 Tip: start with **Internal testing** (instant, share a test link) before
> going to Production.

## ✅ Multiplayer / Voice Verification Checklist

Use this to confirm everything works in **both Option A (Render)** and
**Option B (local)**. (Online features require the server running — see the note
at the top.)

| Test | How to check | Expected |
| ---- | ------------ | -------- |
| Server up | open `/health` | `{"ok":true,...}` |
| Create room | tap **CREATE ROOM** | you get a 5-letter code, enter the waiting room |
| Join room | 2nd device enters the code → **JOIN ROOM** | both players show in the room |
| **Room full** | 3rd device tries the same code | sees **"ROOM IS ALREADY FULL"** |
| Ready + start | both tap **I'M READY** | 3-2-1 countdown → **FIGHT!** |
| Sync | move/punch on one device | mirrored on the other in real time |
| Beam knockback | land a special | opponent launches far away on both screens |
| Leave/rejoin | one player exits | other becomes host; code reusable |
| Text chat | open 💬 and send | message appears on both devices |
| **Voice chat** | both enable Voice + allow mic, use headphones | you can hear each other |

**Voice chat notes:**
- Voice is **peer-to-peer WebRTC**. The browser/app will ask for **microphone
  permission** the first time — you must **Allow** it.
- Always use **headphones/earphones** (the in-game banner reminds you) to avoid
  echo/feedback.
- Voice needs **HTTPS** to work in browsers. Render gives you HTTPS
  automatically. For local Option B over `http://<ip>:3001`, mobile browsers may
  block the mic — use the Render URL or `localhost` for voice testing.
- If both players are behind strict/symmetric NATs, a STUN-only setup can fail.
  The app already uses Google STUN; for 100% reliability across all networks add
  a **TURN server** (e.g. a free Metered/Twilio TURN) to the `iceServers` list
  in `src/net/useMultiplayer.ts`.

> ℹ️ **Option B doesn't show in this code preview** — that's expected. The
> preview only serves the static front-end, not the Node server. The real game
> works when you run `node server.js` locally or deploy to Render. Use
> **PLAY vs CPU** to preview gameplay without a server.
